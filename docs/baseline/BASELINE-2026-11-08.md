## 4. Observation: line endings in generated API docs

Running `npm run docs:api` on Windows marks 5 committed files as modified (`docs/API.md`, `docs/AUTHORIZATION.md`,
`docs/api/openapi.json`, `docs/api/routes.json`, `docs/api/ROF-LMS.postman_collection.json`). The difference is
**line endings only**: `core.autocrlf=true` checks the files out with CRLF while the generator writes LF.
`git diff --ignore-cr-at-eol` is empty, and SHA-256 of `openapi.json` and `routes.json` with CR removed match the
committed versions. The files were restored. CI (Linux) confirms the docs are up to date. Not a defect; a
`.gitattributes` rule (`docs/api/* text eol=lf`) would remove the noise (optional, not done here).

The snapshot records, per operation: method and path, operation ID, tags, roles (`x-roles`), public/protected,
parameters, request body, and every response status with its schema shape; plus every component schema
(properties, types, enums, required fields). Response shapes come from the recorded responses
(`docs/api/response-schemas.json`).

**Compare a future release:**

```bash
npm run docs:api                                   # regenerate docs/api/openapi.json
node scripts/api-snapshot.mjs compare docs/baseline/api-snapshot-2026-11-08.json            # report
node scripts/api-snapshot.mjs compare docs/baseline/api-snapshot-2026-11-08.json --strict   # exit 1 on breaking changes
```

Breaking = operation removed, roles narrowed, public→protected, parameter removed or newly required, response
status removed, response fields removed, schema properties removed or newly required. Everything else is reported
as additive. Verified: the baseline compared with itself reports "identical" (exit 0); a test copy with a
removed operation, a narrowed role and a removed schema field reports 3 breaking changes and exits 1 with `--strict`.
